## 项目上下文摘要（开始界面）

生成时间：2026-09-01 22:20:00

### 1. 相似实现分析

- **实现1**: `src/app/Game.cpp`
  - 模式：`Game` 负责顶层场景切换、输入分发和窗口渲染。
  - 可复用：`SceneType`、`run()` 主循环、资源加载与绘制入口。
  - 需注意：开始界面需要接入现有地图/战斗流程，不能破坏事件和地图逻辑。
- **实现2**: `origin/feature/ui:src/ui/MainMenuView.cpp`
  - 模式：菜单视图只负责背景、按钮和点击命中判断。
  - 可复用：`setFont()`、`setBackground()`、`handleMouseClick()`、`draw()`。
  - 需注意：远端版本只有开始/退出按钮，需要按当前需求扩展为开始/读档。
- **实现3**: `src/ui/EventView.cpp`
  - 模式：界面层独立管理资源缓存、文本绘制和窗口缩放。
  - 可复用：字体与纹理的本地缓存、`sf::Sprite` 缩放、统一的点击反馈写法。
  - 需注意：开始界面背景图应按窗口尺寸铺满，按钮要保证点击区域稳定。

### 2. 项目约定

- **命名约定**: 类型大驼峰，函数与变量小驼峰，常量使用 `k` 前缀。
- **文件组织**: `src/app/` 放流程控制，`src/ui/` 放视图层，`assets/images/menu/` 放开始界面资源。
- **导入顺序**: 本模块头文件、项目内头文件、第三方头文件、标准库头文件。
- **代码风格**: C++17、SFML 3.0.1、头实现分离，中文界面文本直接写入资源或代码。

### 3. 可复用组件清单

- `origin/feature/ui:src/ui/MainMenuView.*`: 菜单视图框架。
- `origin/feature/ui:src/ui/UiHelpers.*`: 按钮、居中文本、命中检测工具。
- `src/app/Game.cpp`: 场景切换、资源初始化、主循环。
- `assets/images/menu/start_screen.png`: 用户提供的开始界面背景。

### 4. 测试策略

- **测试框架**: 现有 CMake + `tests/*.cpp`。
- **测试模式**: 仍以本地构建和启动验证为主，必要时补充单元测试。
- **覆盖要求**: 菜单能显示、开始按钮能进入地图、退出按钮能关闭窗口、战斗和事件原逻辑不回退。

### 5. 依赖和集成点

- **外部依赖**: SFML Graphics 用于按钮与背景绘制。
- **内部依赖**: `Game` 负责读取菜单动作并切换到地图场景。
- **集成方式**: 新增菜单场景，点击开始后生成一局新地图并进入原有地图流程。
- **配置来源**: `CMakeLists.txt` 需把新的 `src/ui/MainMenuView.cpp` 与 `src/ui/UiHelpers.cpp` 纳入构建。

### 6. 技术选型理由

- **为什么用这个方案**: 直接复用远端菜单视图和本地 `Game` 主循环，改动最小。
- **优势**: 菜单和游戏逻辑分层清晰，后续可继续扩展读档或设置按钮。
- **劣势和风险**: 仓库当前已经有多处未完成改动，合并时要避免误伤战斗、事件和地图逻辑。

### 7. 关键风险点

- **边界条件**: 菜单按钮没有资源时要能回退到纯色背景，不能直接崩溃。
- **性能瓶颈**: 开始界面资源只加载一次，影响可以忽略。
- **资源风险**: 背景图路径必须与 CMake 复制后的运行目录一致。
