# 接口与命名约定

本文档是团队协作时的公共约定。所有成员开发前先看这里，新增类、函数、文件时优先遵守本文档，避免最后合并时出现重复类名、函数名不一致、模块互相依赖混乱等问题。

## 1. 总体架构

项目采用 C++17 + SFML 3.0.1，整体按以下层次组织：

```text
main.cpp
  ↓
app/Game
  ↓
Scene 场景
  ↓
combat/card/map/ui 等业务模块
```

推荐目录结构：

```text

│   ├── Game.hpp
│   └── Game.cpp
```

## 2. 成员分工边界

每个人优先只改自己负责的目录。

```text
组长：src/app/、src/core/、main.cpp、CMakeLists.txt
A：src/card/
B：src/combat/
C：src/ui/
D：src/map/
E：assets/、数据表、字体、图片、README 或说明文档
```

公共头文件需要提前讨论，不要随意改别人正在使用的函数签名。

## 3. 命名约定

### 3.1 文件命名

文件名和主要类名保持一致。

```text
Card.hpp
Card.cpp
CombatSystem.hpp
CombatSystem.cpp
BattleView.hpp
BattleView.cpp
```

头文件使用 `.hpp`，实现文件使用 `.cpp`。

### 3.2 类型命名

类、结构体、枚举使用大驼峰命名。

```cpp
class CombatSystem;
struct Card;
enum class CardType;
```

### 3.3 函数命名

函数使用小驼峰命名，动词开头。

```cpp
playCard()
endTurn()
takeDamage()
gainBlock()
drawCard()
```

### 3.4 变量命名

变量使用小驼峰命名，名字表达含义。

```cpp
currentHealth
maxHealth
currentEnergy
handCards
drawPile
```

### 3.5 常量命名

局部常量使用小驼峰，编译期全局常量使用 `k` 前缀。

```cpp
const int cardWidth = 160;
constexpr int kMaxHandSize = 10;
```

### 3.6 Include 约定

先包含本模块头文件，再包含项目内头文件，最后包含第三方和标准库头文件。

```cpp
#include "card/Card.hpp"

#include "combat/Enemy.hpp"
#include "combat/Player.hpp"

#include <SFML/Graphics.hpp>

#include <string>
#include <vector>
```

## 4. 卡牌模块接口

负责成员：A。

卡牌模块只描述卡牌数据和卡牌来源，不直接绘制 UI，不直接控制完整战斗回合。

### 4.1 CardType

文件：`src/card/Card.hpp`

```cpp
enum class CardType
{
    Attack,
    Skill,
    Power
};
```

### 4.2 CardEffectType

文件：`src/card/Card.hpp`

```cpp
enum class CardEffectType
{
    Damage,
    Block,
    Draw,
    GainEnergy,
    ApplyVulnerable,
    ApplyWeak,
    ApplyStrength,
    Discard,
    Exhaust
};
```

效果类型与 JSON 字段对应关系：

```text
Damage：damage
Block：block
Draw：draw
GainEnergy：gain_energy
ApplyVulnerable：apply_vulnerable
ApplyWeak：apply_weak
ApplyStrength：apply_strength
Discard：discard
Exhaust：exhaust
```

### 4.3 CardEffect

文件：`src/card/Card.hpp`

```cpp
struct CardEffect
{
    CardEffectType type;
    int value;
};
```

字段含义：

```text
type：效果类型
value：效果数值，例如伤害值、格挡值、抽牌数量、获得能量数量
```

### 4.4 Card

文件：`src/card/Card.hpp`

```cpp
struct Card
{
    std::string id;
    std::string name;
    CardType type;
    int cost;
    std::string description;
    std::vector<CardEffect> effects;
};
```

字段含义：

```text
id：程序内部使用的唯一标识，例如 strike、defend
name：显示给玩家看的名称
type：卡牌类型
cost：能量消耗
description：卡牌描述文本
effects：卡牌效果列表，按顺序结算
```

JSON 示例：

```json
{
  "id": "pommel_strike",
  "name": "剑柄打击",
  "type": "Attack",
  "cost": 1,
  "description": "造成 9 点伤害。抽 1 张牌。",
  "effects": [
    {
      "type": "damage",
      "value": 9
    },
    {
      "type": "draw",
      "value": 1
    }
  ]
}
```

约定：

```text
普通攻击、防御和机制卡都统一使用 effects。
不要再新增 drawCount、energyGain、vulnerableCount 等零散字段。
多个效果按 JSON 数组顺序结算。
UI 优先显示 description，不直接拼接 effects。
```

### 4.5 CardDatabase

文件：`src/card/CardDatabase.hpp`

```cpp
class CardDatabase
{
public:
    static Card createStrike();
    static Card createDefend();
    static Card createBash();
};
```

第一阶段至少提供三张测试卡：

```text
Strike：1 费，造成 6 点伤害
Defend：1 费，获得 5 点格挡
Bash：2 费，造成 8 点伤害
```

## 5. 战斗模块接口

负责成员：B。

战斗模块负责规则结算，不负责具体绘制。

### 5.1 Player

文件：`src/combat/Player.hpp`

```cpp
class Player
{
public:
    Player(int maxHealth, int maxEnergy);

    void startTurn();
    void endTurn();
    void takeDamage(int amount);
    void gainBlock(int amount);
    bool spendEnergy(int amount);

    int getCurrentHealth() const;
    int getMaxHealth() const;
    int getBlock() const;
    int getCurrentEnergy() const;
    int getMaxEnergy() const;

private:
    int currentHealth;
    int maxHealth;
    int block;
    int currentEnergy;
    int maxEnergy;
};
```

### 5.2 Enemy

文件：`src/combat/Enemy.hpp`

```cpp
class Enemy
{
public:
    Enemy(std::string name, int maxHealth);

    void takeDamage(int amount);
    void setIntentDamage(int amount);

    const std::string& getName() const;
    int getCurrentHealth() const;
    int getMaxHealth() const;
    int getIntentDamage() const;
    bool isDead() const;

private:
    std::string name;
    int currentHealth;
    int maxHealth;
    int intentDamage;
};
```

### 5.3 CombatSystem

文件：`src/combat/CombatSystem.hpp`

```cpp
class CombatSystem
{
public:
    void startBattle();
    void playCard(int handIndex);
    void endPlayerTurn();
    void update();

    const Player& getPlayer() const;
    const Enemy& getEnemy() const;
    const std::vector<Card>& getHandCards() const;

private:
    Player player;
    Enemy enemy;
    std::vector<Card> drawPile;
    std::vector<Card> handCards;
    std::vector<Card> discardPile;
};
```

约定：

```text
playCard 只接收手牌索引，不接收鼠标坐标。
鼠标点击由 UI 层判断，战斗规则由 CombatSystem 结算。
CombatSystem 可以读取 Card，但 Card 不应该依赖 CombatSystem。
```

## 6. UI 模块接口

负责成员：C。

UI 模块负责显示和输入转换，不直接写战斗规则。

### 6.1 CardView

文件：`src/ui/CardView.hpp`

```cpp
class CardView
{
public:
    sf::FloatRect getBounds() const;
    void setPosition(sf::Vector2f position);
    void draw(sf::RenderWindow& window, const Card& card) const;

private:
    sf::Vector2f position;
};
```

### 6.2 BattleView

文件：`src/ui/BattleView.hpp`

```cpp
class BattleView
{
public:
    void handleMouseClick(sf::Vector2f mousePosition, CombatSystem& combat);
    void draw(sf::RenderWindow& window, const CombatSystem& combat);
};
```

约定：

```text
BattleView 可以调用 CombatSystem::playCard。
BattleView 不直接修改 Player 或 Enemy 的血量。
BattleView 只负责把鼠标位置转换成手牌索引。
```

## 9. CMake 整合规则

每新增一个 `.cpp` 文件，都必须加入根目录 `CMakeLists.txt` 的 `add_executable`。

示例：

```cmake
add_executable(SlayTheSpire
    src/main.cpp
    src/app/Game.cpp
    src/card/Card.cpp
    src/card/CardDatabase.cpp
    src/combat/Player.cpp
    src/combat/Enemy.cpp
    src/combat/CombatSystem.cpp
    src/ui/CardView.cpp
    src/ui/BattleView.cpp
    src/map/MapNode.cpp
    src/map/MapGenerator.cpp
)
```

新增头文件 `.hpp` 不一定必须写入 `CMakeLists.txt`，但新增 `.cpp` 必须写入。

## 10. 分支与合并流程

所有人不要直接改 `main` 分支。

```powershell
git switch main
git pull
git switch -c feature/card-system
```

完成后：

```powershell
cmake --preset windows-x64
cmake --build --preset debug
git add .
git commit -m "feat: 添加卡牌系统"
git push -u origin feature/card-system
```

然后在 GitHub 创建 Pull Request，由组长或另一名成员检查后合并。

## 11. 合并前检查清单

提交前必须确认：

```text
能成功 Debug 构建。
新增 .cpp 已加入 CMakeLists.txt。
没有提交 out/、.vs/、exe、dll、obj、pdb 等生成文件。
没有直接修改别人模块的内部实现。
公共接口变更已经通知其他成员。
函数名、类名、文件名符合本文档约定。
```

## 12. 第一阶段目标

第一阶段不要追求完整游戏，先完成一个可运行闭环：

```text
打开游戏
显示玩家、敌人、手牌
点击攻击牌
敌人扣血
点击结束回合
敌人攻击玩家
玩家抽新牌
```

完成这个闭环后，再继续做地图、遗物、更多卡牌、动画和资源替换。
