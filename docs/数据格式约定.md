# 数据格式约定

本文档由 E 组维护，用于约定 `assets/data/` 下 JSON 数据的格式。A 组读取卡牌数据、B 组执行战斗效果、C 组显示 UI 时都以本文档为准。

## 1. 目录

```text
assets/data/
├── cards.json
└── enemies.json
```

## 2. cards.json

`cards.json` 是卡牌列表，根节点是数组。

### 2.1 卡牌字段

```json
{
  "id": "pommel_strike",
  "name": "剑柄打击",
  "type": "Attack",
  "cost": 1,
  "description": "造成 9 点伤害。抽 1 张牌。",
  "effects": [
    {
      "type": "damage",
      "value": 9
    },
    {
      "type": "draw",
      "value": 1
    }
  ]
}
```

字段说明：

```text
id：卡牌唯一标识，只使用小写字母、数字和下划线。
name：显示给玩家看的中文名称。
type：卡牌类型，当前允许 Attack、Skill、Power。
cost：能量消耗，0 或正整数。
description：显示给玩家看的中文描述。
effects：效果数组，按顺序执行。
```

### 2.2 效果字段

```json
{
  "type": "damage",
  "value": 6
}
```

字段说明：

```text
type：效果类型。
value：效果数值。
```

当前允许的效果类型：

```text
damage：造成伤害。
block：获得格挡。
draw：抽牌。
gain_energy：获得能量。
apply_vulnerable：给予易伤。
apply_weak：给予虚弱。
apply_strength：获得力量。
discard：弃牌。
exhaust：消耗当前卡牌。
```

### 2.3 机制卡写法

抽牌卡：

```json
{
  "id": "shrug_it_off",
  "name": "耸肩无视",
  "type": "Skill",
  "cost": 1,
  "description": "获得 8 点格挡。抽 1 张牌。",
  "effects": [
    {
      "type": "block",
      "value": 8
    },
    {
      "type": "draw",
      "value": 1
    }
  ]
}
```

加能量卡：

```json
{
  "id": "seeing_red",
  "name": "盛怒",
  "type": "Skill",
  "cost": 1,
  "description": "获得 2 点能量。消耗。",
  "effects": [
    {
      "type": "gain_energy",
      "value": 2
    },
    {
      "type": "exhaust",
      "value": 1
    }
  ]
}
```

## 3. enemies.json

`enemies.json` 是敌人列表，根节点是数组。

```json
{
  "id": "cultist",
  "name": "教徒",
  "maxHealth": 48,
  "intentDamage": 6,
  "description": "第一阶段普通敌人，适合测试敌人攻击回合。"
}
```

字段说明：

```text
id：敌人唯一标识，只使用小写字母、数字和下划线。
name：显示给玩家看的中文名称。
maxHealth：最大生命值，正整数。
intentDamage：默认攻击意图伤害，0 或正整数。
description：给开发者看的说明，可用于调试面板。
```

## 4. events.json

`events.json` 是事件列表，根节点是数组。事件由阶段和选项组成，UI 只显示当前阶段的选项。

```json
{
  "id": "sacred_nailong",
  "title": "神圣的不明生物",
  "description": "………………",
  "background": "assets/images/event/dungeon_background.png",
  "act": 1,
  "weight": 10,
  "states": [
    {
      "text": "………………",
      "image": "assets/images/event/nailong_laugh.png"
    },
    {
      "text": "哈哈哈哈哈哈哈哈",
      "image": "assets/images/event/nailong_serious.png",
      "sound": "assets/sounds/nailong_laugh.mp3"
    }
  ],
  "options": [
    {
      "text": "看着这个黄色的不明生物，你觉得很神圣",
      "state": 0,
      "next_state": 1,
      "closes_event": 0,
      "effects": []
    }
  ]
}
```

字段说明：

```text
id：事件唯一标识，只使用小写字母、数字和下划线。
title：事件标题。
description：默认事件文本；未填写 states 时会作为第 0 阶段文本。
background：事件背景图路径，可选；路径相对于运行目录。
act：所属幕数。
weight：随机权重。
states：阶段数组，每个阶段可配置 text、image、sound。
title：阶段标题，可选；适合顶部居中显示问题。
left_image/right_image：阶段左右图片，可选；适合并排展示校徽或图标。
overlay_alpha：半透明黑色遮罩透明度，默认 70。
close_on_click：1 表示该阶段无按钮，点击任意位置或按键后关闭事件。
options：选项数组。
state：该选项属于哪个阶段，默认 0。
next_state：点击后切到的阶段索引，未设置表示不切阶段。
closes_event：1 表示点击后关闭事件，0 表示点击后继续停留在事件中。
effects：效果数组，按顺序执行。
```

当前允许的事件效果类型：

```text
heal：恢复生命。
lose_health：失去生命。
gain_gold：获得金币。
lose_gold：失去金币。
lose_all_gold：失去全部金币。
add_card：添加卡牌，parameter 写卡牌 id。
remove_card：删除卡牌，parameter 写卡牌 id。
upgrade_card：升级卡牌，parameter 写卡牌 id。
none：无效果。
```

多阶段事件写法：

```text
初始阶段选项写 state=0、next_state=1、closes_event=0。
后续阶段选项写 state=1，并让 closes_event 使用默认值 1。
点击后会先执行 effects，再根据 closes_event 决定进入下一阶段或关闭事件。
```

## 5. 维护规则

```text
新增机制优先增加 effects 类型，不新增大量零散字段。
新增字段前先通知 A、B、C 组。
删除或重命名字段前先更新本文档。
JSON 文件必须能被正常解析。
id 不要使用中文、空格或短横线。
```
