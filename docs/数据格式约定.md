# 数据格式约定

本文档由 E 组维护，用于约定 `assets/data/` 下 JSON 数据的格式。A 组读取卡牌数据、B 组执行战斗效果、C 组显示 UI、D 组进入地图节点时都以本文档为准。

> 当前接入状态：`events.json` 已由 `EventDatabase` 读取；`cards.json` 和 `enemies.json` 目前仅是资源样例，运行时分别使用 C++ `CardDatabase` 和固定的 `EncounterDefinition`。在加载器完成前，修改 JSON 不会自动改变游戏。完整差距清单见 [实现现状与差距.md](实现现状与差距.md)。

## 1. 目录

```text
assets/data/
├── cards.json
├── enemies.json
└── events.json
```

地图节点图标不放在 `src/map/`，统一放在资源目录：

```text
assets/images/map/
├── node_normal.png
├── node_boss.png
├── node_shop.png
├── node_rest.png
└── node_event.png
```

## 2. cards.json（目标格式，当前未加载）

`cards.json` 是卡牌列表，根节点是数组。

```json
{
  "id": "pommel_strike",
  "name": "剑柄打击",
  "type": "Attack",
  "cost": 1,
  "description": "造成 9 点伤害。抽 1 张牌。",
  "effects": [
    {
      "type": "damage",
      "value": 9
    },
    {
      "type": "draw",
      "value": 1
    }
  ]
}
```

字段说明：

```text
id：卡牌唯一标识，只使用小写字母、数字和下划线。
name：显示给玩家看的中文名称。
type：卡牌类型，当前允许 Attack、Skill、Power。
cost：能量消耗，0 或正整数。
description：显示给玩家看的中文描述。
effects：效果数组，按顺序执行。
```

当前允许的卡牌效果类型：

```text
damage：造成伤害。
block：获得格挡。
draw：抽牌。
gain_energy：获得能量。
apply_vulnerable：给予易伤。
apply_weak：给予虚弱。
apply_strength：获得力量。
discard：弃牌。
exhaust：消耗当前卡牌。
```

机制卡统一写入 `effects`，不要再新增 `drawCount`、`energyGain`、`vulnerableCount` 等零散字段。

## 3. enemies.json（目标格式，当前未加载）

`enemies.json` 是敌人列表，根节点是数组。

```json
{
  "id": "cultist",
  "name": "教徒",
  "maxHealth": 48,
  "intentDamage": 6,
  "description": "第一阶段普通敌人，适合测试敌人攻击回合。"
}
```

字段说明：

```text
id：敌人唯一标识，只使用小写字母、数字和下划线。
name：显示给玩家看的中文名称。
maxHealth：最大生命值，正整数。
intentDamage：默认攻击意图伤害，0 或正整数。
description：给开发者看的说明，可用于调试面板。
```

## 4. events.json

`events.json` 是事件列表，根节点是数组。地图进入 `MapNodeType::Event` 节点后，由 `Game` 调用 `EventSystem::startEvent(eventId)` 打开具体事件。

```json
{
  "id": "sacred_nailong",
  "title": "神圣的不明生物",
  "description": "………………",
  "background": "assets/images/event/dungeon_background.png",
  "act": 1,
  "weight": 10,
  "states": [
    {
      "text": "………………",
      "image": "assets/images/event/nailong_serious.png"
    },
    {
      "text": "哈哈哈哈哈哈哈哈",
      "image": "assets/images/event/nailong_laugh.png",
      "sound": "assets/sounds/nailong_laugh.mp3"
    }
  ],
  "options": [
    {
      "text": "看着这个黄色的不明生物，你觉得很神圣",
      "state": 0,
      "next_state": 1,
      "closes_event": 0,
      "effects": []
    }
  ]
}
```

字段说明：

```text
id：事件唯一标识，只使用小写字母、数字和下划线。
title：事件标题。
description：默认事件文本；未填写 states 时会作为第 0 阶段文本。
background：事件背景图路径，可选；路径相对于运行目录。
act：所属幕数。
weight：随机权重。
states：阶段数组，每个阶段可配置 text、image、left_image、right_image、sound。
overlay_alpha：半透明黑色遮罩透明度，默认 70。
close_on_click：1 表示该阶段无按钮，点击任意位置或按键后关闭事件。
options：选项数组。
state：该选项属于哪个阶段，默认 0。
next_state：点击后切到的阶段索引，未设置表示不切阶段。
closes_event：1 表示点击后关闭事件，0 表示点击后继续停留在事件中。
effects：效果数组，按顺序执行。
```

当前允许的事件效果类型：

```text
heal：恢复生命，不超过最大生命值。
lose_health：失去生命，最低降到 0。
gain_gold：获得金币。
lose_gold：失去指定金币，不足时效果失败。
lose_all_gold：失去全部金币。
add_card：添加卡牌，parameter 写卡牌 id。
remove_card：删除卡牌，parameter 写卡牌 id。
upgrade_card：升级卡牌，parameter 写卡牌 id。
none：无效果。
```

多阶段事件约定：

```text
初始阶段选项写 state=0、next_state=1、closes_event=0。
后续阶段可通过 close_on_click=1 变成结果页，由任意鼠标点击或按键关闭。
选项执行成功后先结算 effects，再切换阶段或关闭事件。
事件关闭时由 EventSystem 标记 visitedEventIds，避免重复出现。
```

## 5. 地图与事件集成

地图节点使用 `src/map/MapNode.hpp`：

```cpp
enum class MapNodeType
{
    Battle,
    Elite,
    Rest,
    Shop,
    Event,
    Boss
};
```

当前最小整合规则：

```text
Battle、Boss：进入战斗场景。
Event：进入事件场景，优先打开 university_choice，已访问后打开 sacred_nailong。
Rest、Shop：暂保留为地图占位，不进入事件系统。
地图从底部 row=0 开始，向上沿 nextNodeIds 前进，不能回退或跳到非连线分支。
当前地图生成器不再生成 Elite 节点；Boss 使用 `node_boss.png`。代码中虽然保留 `Elite` 枚举值，但没有可玩的精英战斗入口。
休息节点只出现在 Boss 前一层，其他普通分支层不会随机生成休息节点。
```

后续正式地图系统只需要在点击 `MapNodeType::Event` 节点时调用事件模块即可，不需要直接处理事件图片、音频和效果。宝箱、问号和战后卡牌奖励需要先新增对应场景和业务接口。

## 6. 维护规则

```text
新增机制优先增加 effects 类型，不新增大量零散字段。
新增字段前先通知相关负责成员。
删除或重命名字段前先更新本文档和对应解析代码。
JSON 文件必须能被正常解析。
id 不要使用中文、空格或短横线。
资源路径应能从 exe 运行目录访问。
```
